# Vision 2030 QR Landing Page Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish a mobile-friendly RTL landing page and stable QR download flow for the supplied strategic-vision PDF.

**Architecture:** Static HTML, CSS, and JavaScript are served directly by GitHub Pages. A local vendored QR library renders the production download-page URL at runtime, while `download.html` resolves the PDF from its own location.

**Tech Stack:** HTML5, CSS3, vanilla JavaScript, Node.js built-in test runner, vendored qrcode-generator, GitHub Actions Pages.

**Spec:** `docs/superpowers/specs/2026-09-26-vision-2030-qr-design.md`

## Global Constraints

- Preserve the supplied PDF byte-for-byte at `documents/vision-2030.pdf`.
- All visible Arabic content is RTL, accessible, and based only on the source cover.
- QR values and PDF links use browser-relative URL resolution; no hardcoded hostname or local URL.
- Ship all runtime assets locally, including the QR library and PDF.

## Review Focus

- GitHub Pages repository-subpath URL produces a download URL ending in `/download.html`.
- QR export is a usable PNG when the canvas is available.
- Clipboard failure gives users readable feedback rather than a silent error.
- Automatic download preserves a manual fallback for mobile browser restrictions.
- Missing PDF produces an accessible error state instead of concealing the failure.
